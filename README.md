# オンゲキ レートビューア

オンゲキNET（ongeki-net.com）から自分のデータを取り出して、レーティング枠・全スコア・プレイ履歴・自己ベスト更新履歴・所持カードを表示するツール。

## ファイル

| ファイル | 内容 |
|---|---|
| `index.html` | ビューア本体（ビルド済み・1ファイル）。ブラウザで直接開ける |
| `dist/bookmarklet.txt` | ブックマークレット（ビューアの「データ取り込み」タブからもコピーできる） |
| `dist/ongeki-viewer.html` | claude.ai アーティファクト公開用（自動取り込みと画像表示は使えない） |
| `collector.js` | ブックマークレットのソース |
| `app/` | ビューアのソース（React 19 + [Astryx](https://github.com/meta/astryx) 0.7.8、Vite で1ファイルにビルド） |
| `app/src/rating.js` | レーティング計算・定数の逆算 |
| `build.js` | `node build.js` でブックマークレットとビューアを再生成する（初回は `app` で `npm install`） |

## 使い方

1. `index.html` を開き、「データ取り込み」タブのボタンをブックマークバーへドラッグする（最初の1回）。
2. 「データ取り込み」タブの「オンゲキNETを開く」でオンゲキNETを開き、そのタブでブックマークレットを実行する。
3. 1分半ほどで、データがビューアに自動で届いて取り込まれる。

ビューアを経由せずにオンゲキNETを開いた場合は、従来どおり `ongeki-data-….json` がダウンロードされるので、「データ取り込み」で読み込む。

自動取り込みは、ビューアが開いたタブ（`window.opener`）に `postMessage` で送る仕組み。送る前にビューアへ確認を送り、返事の送信元がローカルファイル（origin が `null`）のときだけデータを渡す。ビューア側も、オンゲキNET（`https://ongeki-net.com`）以外からのメッセージは無視する。

取り込むたびに、プレイ履歴（NETは最新50件まで）・レーティング推移・自己ベスト更新が積み上がって保存される。保存先はブラウザの localStorage なので、ときどき「バックアップ」で控えを取ること。

## 取得の速さとオンゲキNETへの負担

オンゲキNETは、短時間に連続してアクセスすると「短時間の連続アクセスにより接続が制限されました」（エラー200001）でしばらく使えなくなる。同時に4本・80ms間隔で読んだときに実際に制限された。そのためページの読み込みは開始の間隔を450msあけ、速くするのは読むページ数を減らす方で行っている。

- プレイ詳細: ビューアが内訳を持っているプレイは読まない（前回からの新しいプレイの分だけ）
- カード一覧: 7日に1回だけ読む（カードタブの「次回の取り込みでカードも読み直す」で強制できる）
- ジャケット: まだ持っていないものだけ読む（250ms間隔）

初回はすべて読むので1分強、2回目以降は新しいプレイの数にもよるが10秒前後の見込み。

## レーティング計算（Re:Fresh 以降）

- 全体 = (新曲枠10譜面の合計 + ベスト枠50譜面の合計 + P枠50譜面の合計) ÷ 50（3枠を合計してから小数第3位切り捨て。枠ごとに切り捨てると実データで 0.001 ずれる）
- 単曲レート = 譜面定数 + スコア補正 + ランクボーナス(SS 0.1 / SSS 0.2 / SSS+ 0.3) + ランプ(FC 0.1 / AB 0.3 / AB+ 0.35) + FULL BELL 0.05
- スコア補正: 80万 −6.0 / 90万 −4.0 / 97万 0 / 99万 +0.75 / 100万 +1.25 / 100.75万 +1.75 / 101万 +2.0（間は線形、0.001未満切り捨て）
- P枠の単曲レート = ☆数 × 定数² ÷ 1000（☆: 94/95/96/97/98% で ☆1〜5）
- 新曲枠は「現バージョン」の曲。2026年11月時点では Re:Fresh Act.2 の曲だけが新曲枠で、Re:Fresh（Act.1）の曲はベスト枠。

実データで検証（2026年11月）: 計算値がNETに表示されるレーティングと一致し、3枠に入る譜面もNETの表示と完全一致した。

## 譜面定数の逆算

otoge-db に未登録の譜面は、レベル表記の範囲（"14" → 14.0〜14.6、"14+" → 14.7〜14.9）を候補にして、次の2つで絞り込む（`rating.js` の `inferConstants`）。

1. 公式レート一致: NETのレート対象曲（3枠）のレート合計から出した値が、公式レートと一致する組み合わせだけ残す
2. 並び順: NETのレート対象曲・次点候補は単曲レート順に並ぶので、前後の既知譜面のレートに挟まれる値だけ残す

両方の共通部分を使う。1つに決まった定数は「計」、範囲が残った定数は「?」（範囲の最小値で計算）で表示する。レート対象曲・次点候補に入っていない譜面は逆算できない。

## レート枠の画像化

「画像」タブで、ベスト枠・新曲枠・P枠（またはその組み合わせ）を1枚のPNGにできる。配色（ダーク／ライト）と列数（3列／5列）を選べる。ジャケットは、ブックマークレットがレート対象曲と次点候補の分だけ120pxに縮めて持ってくる（ブラウザの `ongekiViewer.jackets.v1` に保存）。

## プレイ内訳

ブックマークレットはプレイ履歴50件それぞれの詳細ページも読み、判定内訳（CRITICAL BREAK / BREAK / HIT / MISS）、MAX COMBO、BELL、被弾数、ノーツ種別ごとの精度を保存する。自己ベストを更新したプレイは、その内訳ごと「自己ベスト更新履歴」に残る。プラチナスコアの内訳はNETに表示されないため取得できない。
